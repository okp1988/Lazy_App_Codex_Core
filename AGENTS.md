## Project Shape

- This is a single-project Windows Forms app targeting `net8.0-windows` with `UseWindowsForms=true`; the solution contains no separate test project.
- The app is an ADB-backed Android automation runner. `config.json` is the editable runtime script source and is intentionally not copied to build/publish output by the `.csproj`.
- `Form1.cs` owns the main window, global hotkey routing, two independent run-slot states, Remaining/Infinity and offset selection, fixed one-set/two-set client-area sizing, taskbar overlay icons, and opening the config editor. `RunSetLayout.cs` shares existing composition/client-size data with the isolated layout checker.
- `RunSetControl.cs` / `RunSetControl.Designer.cs` own the repeated main-window run-set UI. Both Set 1 and Set 2 use this same control; Set 2 hides the shared Config and Pair / Connect buttons. Keep the control designer-backed, but keep fragile runtime setup such as fixed pixel layout, adaptive Remaining row sizing, and offset dropdown item population in `RunSetControl.cs` so Visual Studio designer rewrites do not break the UI. `CenteredNumericUpDown.cs` centers the native Remaining editor without changing its outer layout.
- Main-window status dots are separate: `statusDot` is global hotkey registration, and `adbStatusDot` is ADB server/device status from the background `adb track-devices` monitor. Hotkey status colors are gold for both primary and secondary hotkeys registered, green for primary only, blue for secondary only, and red for no registered hotkey. The taskbar overlay includes a matching hotkey-status identifier plus one or two run-set identifiers depending on Set 2 visibility. ADB status colors are dark gray for no server/unavailable tracker, red for server with no ready device, green for one ready device, and yellow for multiple ready devices. Dark gray alone does not prove the ADB server stopped.
- The main window supports two run control sets. Set 1 is always visible and uses primary hotkeys. Set 2 is toggled with `Alt+1`, uses secondary/backup hotkeys, and omits Config and Pair / Connect because those actions are shared. The window is not user-resizable or maximizable; it only switches between fixed one-set and two-set client sizes when Set 2 opens or closes, and Run/Stop actions must not resize either set.
- The current compact progress layout fixes the usable client area, not the outer window chrome: one-set client `606 x 292`, two-set client `1200 x 292`, run-set content column `410`, action column `184`, set gap `12`, and `RunSetControl` `594 x 284`. `Form1` derives the outer fixed size with `SizeFromClientSize(...)` so Windows DPI/title-bar differences can add a few outer pixels without squeezing the app contents. If adjusting for another development platform, laptop, DPI, or font context, preserve this profile or add an explicit alternate profile instead of silently changing these values.
- Set 2 secondary hotkeys are registered only while Set 2 is open and are unregistered when Set 2 closes.
- Each run set has its own Device dropdown containing all currently ready `adb track-devices` rows, plus `No Device`. Either panel may be empty; Set 2 selection/running does not require Set 1 to have a device. The same device may be selected in both panels; simultaneous commands can interleave and no phone-level serialization is added. A newly-ready device event fills only one visible, idle empty panel (including deliberate No Device), preferring Set 1 then Set 2. Startup/simultaneous arrivals use the first listed newly-ready device; existing selections/running assignments stay unchanged. Cached metadata/config/run-state/visibility refreshes do not auto-fill empty selections, and hidden stopped Set 2 is ineligible. Device loss stops only affected running sets without transferring another set's device. Wi-Fi display omits the port, but commands retain the full selected serial. `AdbDeviceSnapshotReader.cs` publishes complete tracker snapshots, including empty snapshots; details and D-009 evidence are in `docs/PROGRESS.md`.
- Each run set has a Remaining number box and Infinity checkbox between Run and Offset. Finite input is at most 99; Plans use the last N individual cycles and cap input at `min(total, 99)`. Completed cycles decrement the count; manual Stop/Start retains it. Explicit target reselection reloads defaults. Normal finite completion reloads the latest configured count while preserving valid Target, Offset, Tag and Device selections, including same-target offsets in other idle panels; invalid-selection safeguards and ordinary config/manual Stop reload behavior remain unchanged. Infinity is available only for Scripts/Sequences. Details and D-012 evidence are in `docs/PROGRESS.md`; `SkipPickerControl.cs` is retained unused legacy source, not the active UI.
- `SearchableDropdown.cs` is the custom main Script/Sequence/Run Plan picker. Its popup owns search text and clears it on close; the main field should only show the selected item. When the popup opens, highlight the current selected item if it is still present in the filtered list.
- `CountdownProgressControl.cs` draws the main countdown/progress bar. `ScriptRunner` status updates include countdown timestamps and a six-chip timeline for current and next actions. The main window clock timer should run only while at least one run set is active.
- `ConfigEditorForm.cs` is a hand-built WinForms editor for the config categories: `settings`, `offset`, `scripts`, `sequences`, and `runPlans`.
- `WirelessAdbConnectForm.cs` is the manual Wireless ADB Pair / Connect helper opened from the main window below Config. It supports Pair and Connect actions, Restart Server, a Device dropdown with Manual Input at index 0, fixed-separator IPv4 entry, numeric-only Port and Pair Code fields, Enter to invoke Try, and Title Case display/status text except for user-entered values.
- The Config Editor also exposes a Devices tab backed by `settings.devices`. Device names default to `manufacturer : model`, Wi-Fi device keys are stored without the port, user names are editable, Sync is only enabled for currently connected ready devices, and disconnected saved devices may still be renamed or deleted.
- In `ConfigEditorForm`, new button rows are easy to clip at the bottom. Prefer `TableLayoutPanel` rows with explicit heights and docked buttons over auto-sized or tight `FlowLayoutPanel` rows, and leave enough bottom padding when placing buttons inside scrollable/editor panels.
- `ConfigEditorForm` opens the shared Script/Sequence Track Touch window only when a ready ADB device is available. It passes the current ready-device status plus saved device-name mapping to `TrackTouchForm` and keeps at most one owned Track Touch window open.
- `TrackTouchForm.cs` owns touch tracking and coordinate testing. Its Device dropdown lists currently ready devices by saved friendly name while retaining the full serial for ADB. Switching devices stops the old tracker before starting a new one. It prefers the effective `wm size` override, reads touch ABS ranges per `/dev/input/event*` device, starts one long-running `adb shell getevent -l` process, and maps coordinates only with the event device that emitted the line. It shows live scaled coordinates for taps and drags plus raw/range diagnostics, records completed point gestures only (not drags) in history with device name and time, copies a double-clicked history point into the test fields, and sends Test Tap through the selected device. It must stop tracking on device loss, device switch, or window/editor close.
- `ScriptConfigRespository.cs` loads, migrates, normalizes, and saves `config.json`; preserve its alias support when changing script/config behavior.
- `ScriptRunner.cs` expands normalized steps into ADB commands and sleeps; it supports an `ADB OFF` path where commands are skipped but statuses/timing still update.
- `AdbShellController.cs` shells out to `C:\adb\adb.exe` by default and works in physical device-pixel coordinates.
- `AppLogger.cs` writes daily logs under `AppContext.BaseDirectory\logs` and deletes logs older than 7 days at startup.

## Config Rules

- `config.json` supports both top-level legacy scripts and the current `{ settings, offset, scripts, sequences, runPlans }` shape; repository loading skips those category keys when scanning legacy scripts.
- Settings are migrated from `hotkeyStartStopToggle` to `hotkeyStart`; do not reintroduce the old setting as the canonical key. Backup hotkeys use `hotkeyBackupStart` and `hotkeyBackupStop`, may be blank, and control Set 2 while Set 2 is open. They are registered independently from the primary Set 1 hotkeys.
- Offset profiles are named `s<number>` and selected by matching digits in the script name; fallback keys include `offsetX`/`offsetY`, `ox`/`oy`, `x`/`y`, and `s`.
- Script aliases are meaningful API: `d`, `imin`, `imax`, `i`, `config`, `steps`, nested `steps` with `repeat`/`rep`, `a`, `s`, `s2`, `p`, `p2`, `r`, `t`, and `o` must remain compatible unless intentionally migrated.
- Runtime normalization accepts `leftclick` as `left`, `rightclick`/`back` as `right`, and `wait` as `delay`. Directional drag names are accepted but currently normalize to generic `drag`; unknown actions currently fall back to `left`. These observed limitations are recorded in `docs/PROGRESS.md` and are not approved fixes in this documentation task.
- Only left-click steps receive the selected UI offset. Standalone Scripts use it on their first Left per cycle; Sequences share at most one offset allowance across the entire cycle, including referenced scripts/repeats/direct actions and Sequences inside Run Plans. Reset the allowance for each new cycle, not each nested script. Preserve existing direct-action Back/Drag eligibility; details and D-010 evidence are in `docs/PROGRESS.md`. A per-step `offset`/`o` value of `x` or `y` overrides the axis selected in the main window.
- The config editor writes compact script output (`d`, `imin`, `imax`, `emin`, `config`, `a`, `s`, `s2`, `r`, `t`) and exposes `left`, `right`, `drag`, and `delay` in its action grids. A Delay step performs no ADB command and uses `t` as its delay range; legacy `wait` action input normalizes to `delay`.
- Sequences are first-class config entries. Sequence items may reference scripts by `scriptId` or contain direct actions; sequences must not reference other sequences.
- Run Plans are first-class config entries. Run Plan items may reference scripts or sequences by stable ID and store an item repeat count. Run Plans must not reference other Run Plans.
- `settings.tag` is the canonical tag list and may be empty. Scripts, sequences, and run plans may store one configured `tag` or a blank tag; selecting a tag in the main filter shows that tag plus blank-tag entries. The main window tag filter always includes `All` at index 0 before configured tags.
- `settings.devices` is the canonical device history/name map. It stores `name`, `manufacturer`, `model`, `lastSerial`, and `lastSeen`; automatic sync may fill missing data for new devices but must not overwrite existing manufacturer/model conflicts silently.
- Wireless ADB Connect may create or update a Wi-Fi device entry by IP address. Successful Connect updates `lastSerial` to the current `IP:Port` and refreshes `lastSeen`; Pair success alone does not mean the device is connected.
- Script and Sequence `hide` controls whether the entry appears in the main Script/Sequence/Run Plan dropdown. Hidden scripts still remain valid sequence script items, and hidden sequences still remain valid Run Plan items.

## Run Behavior

- Start/stop is cancellation-token based. Each run set owns its own cancellation token and task; `StopRunAsync` cancels the selected set and waits for that set's task. Avoid fire-and-forget script execution paths.
- `Duration <= 0` means run indefinitely. Positive duration is a loop count, not seconds.
- Step sleeps and loop interval sleeps are randomized inclusively; inverted min/max values are swapped in `ScriptRunner.RandomBetween`.
- Script and Sequence `emin` is an optional minimum cycle time in seconds. It cannot exceed the displayed max cycle time; runtime computes a cycle plan before execution and re-randomizes the lowest flexible waits upward until the plan reaches `emin`. If `emin` equals max cycle time, all flexible waits use their maximum values.
- Run Plan item repeat overrides the referenced Script/Sequence saved `Duration` only for that item. Referenced targets keep their own internals: `emin`, `imin`, `imax`, sleeps, Sequence item delays, offsets, ADB OFF behavior, cancellation, and live status updates. A Run Plan can alternate the same target multiple times and must preserve the configured item order exactly.
- Remaining/Infinity controls are disabled during a run, but fully completed cycles still decrement the finite value. Interrupted cycles are not deducted. Plans derive their internal skip from total minus Remaining; direct Scripts/Sequences use Remaining as their runtime loop count. Preserve manual-stop retention and the finite-completion reload exception; do not restore the old Skip reset behavior.
- One asynchronous, non-looping completion tone per panel follows normal completion of its entire finite Script, Sequence or Run Plan at zero after stopping; never beep per cycle/Plan item, manual Stop, cancellation, device loss, error, Infinity or app closing. `CompletionTone.cs` generates a stronger 300ms tone in memory without external audio assets or volume-setting changes. Normal finite completion still reloads the configured count; Windows/output-device volume governs audibility, and near-simultaneous completions may restart/overlap rather than queue distinct audible tones. D-011 evidence is in `docs/PROGRESS.md`; live sound/device behavior is not verified by build/source review.
- Config and Pair / Connect remain accessible during runs. Each active run captures its target/library, resolved offsets, device, timing, and run options; dialog repositories are separate, stopped slots load saved changes, and global hotkey remapping waits until both slots stop. Only Restart Server is disabled while either slot runs, because it affects the ADB server globally.
- Drag steps use `s2`/`scrX2`/`scrY2` when supplied. Without an explicit end point, the current runner uses the start point as the end point; directional endpoint derivation is an observed limitation recorded in `docs/PROGRESS.md`.
- Delay steps use their `t` minimum/maximum as a randomized cancellable wait and appear as `DELAY` in live status/timeline. A leading Delay does not consume the selected offset; the first following applicable left-click receives it.
- Global hotkeys are unregistered when the window is minimized and re-registered when restored/activated; this behavior is logged in the UI log and warning log. Secondary hotkeys are included in registration only while Set 2 is open.
- If active start and stop hotkeys are the same, only one hotkey is registered and it toggles start/stop.
- In-app shortcuts are `Alt+1` for open/close Set 2, `Alt+2` for Config, and `Alt+3` for Pair / Connect. `Esc` stops active runs from the main window, calls the Config close-button flow in Config, and closes Pair / Connect.

## Local Runtime Assumptions

- ADB is expected at `C:\adb\adb.exe` unless code is changed to pass a different path.
- ADB status checks should not block opening Config. First check localhost port `5037`; only start the background `adb track-devices` monitor when the server is already listening. While the server/monitor is unavailable, the existing NoServer recovery timer retries every 10 seconds; Run/Config actions and Wireless helper close/restart can request recovery sooner. Healthy device changes stream continuously, including valid empty lists, and stop the retry timer. Pressing Run refreshes ADB status before validating the target; trust cached no-device status only when the monitor is healthy, otherwise attempt recovery. Run starts only when a ready device is selected, and selected-device loss stops/notifies only the affected run set.
- Reuse a tracker only when its process is alive and stdout reader task is active/not marked stopped. Reader EOF/error or process exit marks it unavailable for existing recovery paths. Detach stopped trackers before disposal, reject their queued callbacks, and keep current terminal status from being overwritten by an older first-snapshot result. This recovers app-owned monitoring, not the ADB server or wireless connection; implementation/verification evidence is in `docs/PROGRESS.md` (D-008).
- If `adb track-devices` starts successfully and remains healthy but does not emit an initial device block before the Run timeout, treat that as red/no ready device rather than dark gray/unavailable. Reader failure or process exit must retain the unavailable status and recovery path instead.
- ADB monitor/run gating changes should use the existing `LogAdbWarning(...)` path, which prefixes messages with `[ADB]` and writes through `AppLogger.LogWarning`: trigger/start/reuse/recovery, process/reader state, port check result, complete snapshot rows/ready count/state, stdout EOF/error byte counts, stderr/exit, and Run allow/block.
- Do not add a separate polling/health-check path to cover `track-devices` bugs. `adbStatusDot` is driven by complete snapshots, stdout close/reader error, process exit, and the existing NoServer recovery timer; stderr is diagnostic logging, not by itself a status transition.
- Framed tracker output may expand LF to CRLF without changing the declared LF-byte payload length. The reader counts logical UTF-8 payload bytes, consumes actual CRLF-expanded bytes and buffers split trailing CR; retain complete LF/framed/plain/empty snapshots. D-008 capture/parser evidence is in `docs/PROGRESS.md`. The separate reported temporary input freeze remains unresolved in Discussion; parser/build checks do not establish its cause or fix.
- Wireless ADB setup is manual; `docs/PROGRESS.md` records `adb pair`, `adb connect`, `adb devices`, `adb disconnect`, `adb start-server`, and `adb kill-server` usage.
- Pair / Connect is a manual helper for changing wireless debugging ports and restarting the ADB server. Do not add automatic background reconnect loops or port scanning.
- Pair / Connect uses Try as the form accept action, so Enter must invoke the currently selected Pair or Connect operation while Esc closes the helper.
- `config.json` in the repo is the file loaded by `Form1` via `new ScriptConfigRepository("config.json")`; changing the working directory changes which config file is used.
- The app can be used without executing ADB actions when `IsAdbActionEnabled` is false, but the UI still plans steps and waits through configured sleeps.
